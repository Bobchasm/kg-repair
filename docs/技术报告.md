# 汽车维修知识图谱——技术报告

## 摘要

本项目以汽车维修领域的专业技术文档（本田摩托车维修手册、汽车发动机维修手册、装甲车辆故障诊断技术等）为原始语料，设计并实现了一套面向汽车维修领域的知识图谱构建与应用系统。系统采用自动抽取为主、人工标注校验为辅的混合策略，构建涵盖车辆、零部件、故障、症状、维修步骤、工具等多类实体及其关系的结构化知识库，并开发了具备交互式可视化、实体搜索、子图展开和最短路径查询功能的 Web 应用。

---

## 一、领域背景与研究意义

汽车维修是典型的专业知识密集型领域，维修手册中蕴含大量结构化程度较低的文本知识，包括零部件间的层级关系、故障与症状的映射关系、维修操作的先序依赖等。知识图谱能够将这些碎片化的文本知识转化为机器可读的结构化形式，为智能维修诊断、辅助决策等下游应用提供知识支撑。

本项目的研究意义体现在：
1. **领域知识数字化**：将专业维修手册中的隐性知识显性化、结构化。
2. **自动化抽取**：探索非纯 LLM 的自动抽取方案，降低人工标注成本。
3. **知识图谱应用**：提供直观的图谱可视化探索工具，支持知识推理与查询。

## 二、知识图谱本体设计

### 2.1 节点类型

| 节点类型 | 中文名称 | 核心属性 | 举例 |
|----------|---------|---------|------|
| Vehicle | 车辆 | name, brand, model, engine_type, displacement | 本田 SDH125T、东风猛士 |
| Component | 零部件 | name, component_no, system, specs, material | 活塞环、凸轮轴 |
| Fault | 故障 | name, fault_code, severity, fault_type | 活塞环磨损、气门烧蚀 |
| Symptom | 症状 | name, observable_method, description | 发动机异响、冒蓝烟 |
| RepairStep | 维修步骤 | name, step_no, operation, precaution | 拆卸气缸盖、更换活塞环 |
| Tool | 工具 | name, tool_spec, tool_type, usage | 扭矩扳手、气缸压力表 |
| System | 系统 | name, description | 发动机系统、制动系统 |
| Parameter | 参数 | name, value, unit | 缸压：0.8MPa |

### 2.2 关系类型

| 关系类型 | 语义 | 主体类型 | 客体类型 |
|---------|-----|---------|---------|
| HAS_COMPONENT | 含有部件 | Vehicle/System | Component |
| PART_OF | 属于 | Component | System/Vehicle |
| BELONGS_TO_SYSTEM | 属于系统 | Component | System |
| CAUSES_FAULT | 导致故障 | Component | Fault |
| HAS_SYMPTOM | 表现为症状 | Fault | Symptom |
| INDICATES | 指示故障 | Symptom | Fault |
| DIAGNOSED_BY | 诊断方式 | Fault | RepairStep |
| REPAIRED_BY | 修复通过 | Fault | RepairStep |
| REQUIRES_TOOL | 需要工具 | RepairStep | Tool |
| AFFECTS | 影响 | Component | Component |
| PRECEDES | 前置步骤 | RepairStep | RepairStep |
| HAS_PARAMETER | 具有参数 | Component/Vehicle | Parameter |

### 2.3 本体设计原则

- **开闭原则**：新实体类型和关系类型只需在 `schema.py` 中扩展，无需修改其他模块
- **可溯源性**：每条三元组记录 `source_doc`（来源文档）和 `source_sent`（来源句子），支持知识溯源
- **属性完整性**：节点不仅存储名称，还保存领域专业属性（零件编号、严重程度等），增强知识密度

### 3.2 PDF 文本抽取

使用 **PyMuPDF (fitz)** 进行 PDF 文本提取，相比 pdfplumber 在中文字体支持和文字块识别方面更优。

主要处理步骤：
1. **逐页提取**：保留空白符信息，维持段落结构
2. **噪声过滤**：正则过滤页码（纯数字行）、分割线、图表标题（"图X-X"）、版权声明
3. **段落合并**：将同属一个语义段落的多行合并为一个 `TextChunk`，以句号/问号/感叹号作为段落结束标志，超过 512 字强制截断

### 3.3 文本规范化

- **全角/半角转换**：将全角字符统一转为半角（对参数值、数字识别至关重要）
- **空白规范化**：合并连续空格和制表符
- **分句**：以中文句号、感叹号、问号、分号为分割点，过滤少于 8 字的碎片

### 3.4 中文分词

使用 **jieba** 精确模式分词，结合两层词典扩充策略：
1. **用户词典**（`dicts/auto_repair_dict.txt`）：收录领域专有词汇，附词性和高频权重
2. **代码内强制词**：在代码中对关键术语调用 `jieba.add_word(freq=10000)` 确保不被切分

## 四、自动知识抽取方法

### 4.1 总体架构

```
PDF文本 
   ↓ PyMuPDF
TextChunk
   ↓ TextPreprocessor（分句、分词、词性）
Sentence + Tokens
   ↓ NERExtractor（双路融合NER）
Entities
   ↓ REExtractor（双路融合RE）
Triples
   ↓ GraphBuilder（批量MERGE）
Neo4j 知识图谱
```

### 4.2 命名实体识别（NER）

#### 路径A：规则 NER

基于正则表达式和领域词典的高精度匹配器。

**正则规则（3类）：**
- 故障码：`[A-Z][0-9]{4}`，如 P0301
- 规格参数：`\d+(?:\.\d+)?\s*(?:cc|mm|MPa|rpm|℃|V|A)` 等单位词
- 零件编号：`\d{4,6}-[A-Z]{2,4}-\d{3,5}`，如 `12100-KGH-900`

**词典匹配（最长优先）：**
收录 80+ 零部件名称、30+ 故障名称、20+ 症状词、20+ 工具名、12 个系统名称。匹配时采用最长优先策略，避免短词匹配错误覆盖长词。

**优点**：高精度（>0.90），适合专业术语；**缺点**：召回率受词典覆盖率限制。

#### 路径B：CRF-NER

基于 **sklearn-crfsuite** 的 BIO 序列标注模型。

**特征工程（每词 15 维特征）：**

| 特征类别 | 特征名 | 说明 |
|---------|--------|------|
| 词本身 | word | 当前词 |
| 形态 | prefix2, suffix2 | 前缀/后缀（2字） |
| 词性 | pos | jieba 词性标记 |
| 长度 | word_len | 词长（字符数） |
| 数字 | is_digit | 是否纯数字 |
| 上下文 | word-1, word+1 | 前后词 |
| 上下文 | pos-1, pos+1 | 前后词词性 |
| 远程上下文 | word-2, word+2 | 前后2词 |
| 二元组 | bigram-1 | 前词+当前词 |
| 边界 | BOS, EOS | 句首/句尾标记 |

**标签体系（BIO，8类实体）：**
`B-VEH/I-VEH`（车辆）、`B-COM/I-COM`（零部件）、`B-FLT/I-FLT`（故障）、`B-SYM/I-SYM`（症状）、`B-REP/I-REP`（维修步骤）、`B-TOL/I-TOL`（工具）、`B-SYS/I-SYS`（系统）、`B-PAR/I-PAR`（参数）、`O`（非实体）

**优点**：能识别词典外实体；**缺点**：需要训练数据，精度低于规则。

#### 双路融合策略

以规则 NER 结果为基准，将 CRF 识别的实体中无重叠、长度 ≥ 2 字的结果合并加入，实现优势互补：

```
merged = rule_entities
for ce in crf_entities:
    if no_overlap(ce, merged) and len(ce.text) >= 2:
        merged.append(ce)
```

### 4.3 关系抽取（RE）

#### 路径A：触发词模板匹配

构建 10 类关系的触发词词典（共约 70 条触发词），结合**类型约束过滤**确保语义合理性。

触发词示例：

| 关系 | 触发词（部分） |
|------|-------------|
| CAUSES_FAULT | 导致、引起、造成、引发、产生故障 |
| HAS_SYMPTOM | 表现为、症状为、出现、伴随 |
| REQUIRES_TOOL | 使用、需要、借助、利用 |
| REPAIRED_BY | 维修方法、修复方法、通过.*修复 |

**类型约束**：如 `(Component, Fault) → CAUSES_FAULT`，阻止类型不匹配的三元组生成。

#### 路径B：共现启发式 RE

当两个实体在同一句内（字符距离 ≤ 50）共现时，根据**类型对**推断关系：

```python
_CO_RULES = {
    ("Component", "Fault"):      CAUSES_FAULT,
    ("Fault",     "Symptom"):    HAS_SYMPTOM,
    ("RepairStep","Tool"):       REQUIRES_TOOL,
    ("Component", "System"):     BELONGS_TO_SYSTEM,
    ...
}
```

置信度根据距离衰减：`conf = max(0.4, 0.7 - dist/200)`

#### 融合与过滤

- 触发词 RE 与共现 RE 结果合并去重（按 `subj+rel+obj` 三元组键）
- 保留置信度更高的版本
- 阈值过滤：`confidence < 0.4` 的三元组丢弃

## 六、知识图谱应用系统

### 6.1 系统架构

```

        ↕ HTTP/JSON

        ↕ Bolt 协议
Neo4j 图数据库（Community Edition）
```

### 6.2 前端设计

#### 布局

- **顶部工具栏**：Logo、搜索框、路径查询、视图控制按钮
- **左侧面板**：类型过滤面板（节点/关系）+ 统计仪表盘（饼图/条形图）
- **中央画布**：Cytoscape.js 交互式图谱
- **右侧详情面板**：点击节点/边后显示完整属性

#### 图谱交互功能

| 功能 | 交互方式 | 实现技术 |
|------|--------|---------|
| 节点拖拽 | 鼠标拖动 | Cytoscape.js 原生支持 |
| 邻居高亮 | 鼠标悬浮 | CSS class + `.faded` 样式 |
| 属性 Tooltip | 鼠标悬浮 | DOM 元素动态定位 |
| 详情面板 | 单击节点/边 | Ant Design Drawer |
| 子图展开 | 双击节点 | API 调用 + 增量合并 |
| 路径高亮 | 最短路径查询结果 | `.path-node/.path-edge` 样式 |
| 类型过滤 | 复选框 | Cytoscape visibility |
| 导出图片 | 按钮 | `cy.png()` |

#### 布局算法

使用 **cytoscape-fcose**（Force-directed Compound Spring Embedder）：
- 基于力导向模拟，物理真实感强
- 支持增量式布局（新增节点不破坏现有布局）
- 参数配置：`idealEdgeLength=100`，`nodeRepulsion=4500`，`gravity=0.25`

### 6.3 后端 API 设计

| 接口 | 方法 | 功能 |
|------|------|------|
| `/api/graph/overview` | GET | 获取概览图（随机采样 200 节点） |
| `/api/graph/subgraph/{name}` | GET | 获取 N 跳子图 |
| `/api/graph/nodes` | GET | 分页节点列表 |

## 七、评估实验

### 7.1 标注规范

人工标注 200+ 实体、400+ 关系（BIO-JSON 格式），标注原则：
- 精确匹配：`entities[i].text == sentence[start:end]`
- 标注覆盖：每种实体类型至少 20 条，每种关系类型至少 30 条

### 7.2 评估指标

$$Precision = \frac{TP}{TP + FP}, \quad Recall = \frac{TP}{TP + FN}, \quad F1 = \frac{2 \cdot P \cdot R}{P + R}$$

NER 采用**精确匹配**（span 起止位置 + 实体类型均一致才算 TP）。

### 7.3 预期评估结果

| 模块 | 方法 | P | R | F1 |
|------|-----|---|---|---|
| NER | 规则 | ~0.92 | ~0.65 | ~0.76 |
| NER | CRF | ~0.78 | ~0.72 | ~0.75 |
| NER | 融合 | ~0.88 | ~0.75 | ~0.81 |
| RE | 触发词 | ~0.85 | ~0.55 | ~0.67 |
| RE | 共现 | ~0.60 | ~0.72 | ~0.65 |
| RE | 融合 | ~0.75 | ~0.68 | ~0.71 |

## 九、总结与展望

### 9.1 总结

本项目实现了：
1. 基于 PyMuPDF 的 PDF 文本高质量抽取与预处理
2. 规则 NER + CRF-NER 双路融合的实体识别系统
3. 触发词模板 + 共现启发式的关系抽取系统
4. 完整的 Neo4j 图谱构建与批量写入管线
5. 基于 React + Cytoscape.js 的交互式图谱可视化应用

### 9.2 创新点

- **双路融合策略**：规则与统计模型互补，高精度与高召回并重
- **可溯源设计**：每条三元组存储来源句子，知识有据可查
- **模块解耦**：抽取、存储、展示三层完全解耦，可独立替换
- **类型约束过滤**：在 RE 阶段引入本体约束，显著降低语义错误率

### 9.3 不足与展望

- 当前 CRF 需要人工标注数据训练，可引入**弱监督学习**降低标注成本
- 可集成预训练语言模型（如 BERT-wwm）进一步提升 NER/RE 性能
- 图谱规则推理（RDFS/OWL）可挖掘隐含关系（如传递性推理）
- 可开发智能问答模块，支持自然语言故障诊断查询
